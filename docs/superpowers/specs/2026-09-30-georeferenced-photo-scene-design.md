# 사진 기반 자산을 실제 축척으로 통합하는 제주 3D 장면 설계

**범위:** 기존 탐라–한림 부분 장면의 신창 현장을 첫 대상으로 삼는다. 사용자는 지도 한 화면에서 실제 좌표의 지형·시설·전력망을 확대해 본다. 로드뷰 패널이나 별도 사진 뷰어는 만들지 않는다. 이 문서는 기존 [디지털 트윈 설계](../../../jeju_power_grid_digital_twin_design.md)의 사진·3D 부분을 현재 자료 상태에 맞게 구체화한다.

## 성공 기준과 표현 한계

장면의 좌표계는 현재 `EPSG:32652`, 수직 기준은 `EPSG:3855`(EGM2008), 축은 `x=동, y=위, z=남`, 단위는 1 unit = 1 m로 유지한다. 이미 생성한 DSM 지형, 영상 UV, 건물 GIS 위치, 발전소·선로 원천 좌표를 움직이거나 수직 과장하지 않는다. 가까이 확대했을 때 사진을 참고해 만든 시설 자산이 같은 장면에 놓이고, 확인된 공적 치수는 미터 단위로 맞아야 한다. 측량되지 않은 표면·후면·시설 배치와 원천 GIS 자체의 위치 오차는 실측 정확도로 주장하지 않는다.

사진 확대·초해상도는 화소를 늘릴 뿐 가려진 형상, 촬영 자세, 기준 길이를 복원하지 않는다. 단일 사진 TRELLIS.2 결과는 시각적 후보 자산이다. 지형은 사진 생성물이 아니라 현재의 고도 DSM에 실제 영상 텍스처를 정합한 메시를 기준으로 한다. 현장 다중시점 복원이 가능해지면 동일한 자산 입력 계약에 COLMAP/OpenDroneMap 결과를 넣을 수 있지만, 지금은 별도 복원 시스템을 만들지 않는다.

## 입력과 데이터 경계

GPU 서버의 `inference/run.py`가 이미 사진 → `asset.glb`·`metadata.json`을 생성한다. `renderers/twin/build_local.py`가 풍력·계통·지형을 하나의 `var/rendering/local/scene.glb`에 합치고, 기존 웹 장면과 Omniverse가 이를 읽는다. 이 두 경로를 재사용한다. 사진 원본, 생성 GLB, 장면 GLB는 Git에 넣지 않고 출처·해시·변경 내용은 manifest에 남긴다. Rust API·Redis·WebSocket은 이 정적 자산의 생성이나 축척 결정에 관여하지 않는다.

현재 VisitJeju 참고 사진 36장은 개별 재구성 이용 조건, 카메라 위치·자세, 기준 길이가 없으므로 생성·배포 입력에서 제외한다. CC BY-SA 4.0인 Commons 신창 사진 3장은 출처가 확인됐으나 개별 시설 ID·카메라 자세·기준 길이가 없다. 신창 09 단일 사진의 TRELLIS.2 결과는 전경 등대가 주형상으로 만들어졌으므로 풍력 자산으로 채택하지 않는다. 사진별 사용 허락, 대상 시설 일치, 기준 치수는 각각 독립적으로 검증한다.

## 좌표·축척 계약과 합성

각 채택 자산에는 `facility_id`, 사진·생성 결과 hash/라이선스, 시설 동일성·실제 기준 길이·방향의 확인 근거, 자산의 기준점과 위쪽 축, 자산 내부의 해당 길이, 검증 상태를 기록한다. WGS84 시설 좌표와 EGM2008 수직 기준은 새로 추측하지 않고 기존 시설 manifest와 장면 프레임에서 가져온다. 빈 값은 임의의 기본값으로 채우지 않는다. 채택 조건이 충족되지 않으면 현재의 추정 시설 메시를 유지한다.

좌표는 기존 장면 프레임으로 변환한다. 시설 기준점의 투영 좌표가 `(E,N)`, 장면 원점이 `(E₀,N₀)`이면 `x=E−E₀`, `z=N₀−N`, `y=H_EGM2008`이다. 한 개의 공인 길이 `L_m`와 모델 내 대응 길이 `L_asset`이 확인되면 균일 축척 `s=L_m/L_asset`을 적용한다. 예를 들어 풍력의 공개 회전자 직경 91.59 m는 회전자 모델의 직경 검증에만 사용한다. 그 값만으로 허브 높이·기초 깊이·개별 터빈 동일성은 확정하지 않는다. 회전 방향이나 기준점이 불명확하면 자동 배치를 중단한다. 육상 접지 높이는 해당 위치의 기존 지형과 대조하고, 해상 기초는 조위·해저 수심을 임의로 추정해 맞추지 않는다.

검증된 자산만 `build_local.py`에서 기존 노드를 대체하거나 동일 시설 노드에 연결한다. 원래 시설 ID, 선택·레이어 동작, 카메라, 전력선 위치, 통합 GLB 출력 경로는 유지한다. 회전자처럼 움직이는 부품은 pivot 검증 전 기존 애니메이션 메시를 대체하지 않는다. 하나의 GLB를 웹 지도와 Omniverse가 공유하므로 두 화면의 배치가 다르게 변하지 않는다.

## 실패 처리와 검증

입력 manifest의 필수 출처·좌표·치수·축·ID가 없거나, 사진/GLB hash가 달라지거나, 생성 자산이 다른 물체를 나타내면 합성을 거부한다. 실패해도 기존 3D 장면은 제공하며 검증되지 않은 자산은 UI에 표시하지 않는다. 채택 자산에는 `photo_derived_estimated_geometry`와 검증된 길이·확인되지 않은 항목을 분리해 표시한다.

최소 검증은 (1) 대상 시설 ID가 기존 manifest에 유일하게 존재함, (2) 투영 후 기준점이 원천 좌표로 역변환됨, (3) GLB 길이가 입력 공인 길이와 수치적으로 일치함, (4) 정합된 지형의 1:1 높이와 기존 시설·선로가 변하지 않음, (5) 웹 근접·광역 및 Omniverse 캡처에서 같은 위치에 보임이다. 이는 수치 변환과 통합 검증이지 사진만으로 실측 형상을 입증하는 검사는 아니다.

첫 구현의 완료 기준은 **검증 가능한 사진 자산이 있을 때만 배치하는 입력·합성 경로**다. 현 보유 사진으로 해당 시설을 특정할 수 없으면 실제 사진 생성 자산 0개가 올바른 결과다. 실사 시설 복원을 완료하려면 같은 대상의 사용 가능한 여러 방향 원본과 시설 ID 대응, 최소 한 기준 길이 및 위치 기준을 추가 확보해야 한다.

근거: [TRELLIS.2 공식 사용 예제](https://github.com/microsoft/TRELLIS.2)는 이미지에서 텍스처 GLB를 생성한다. [OpenDroneMap의 중첩 촬영 안내](https://docs.opendronemap.org/flying/)와 [지상 기준점 형식](https://docs.opendronemap.org/gcp/)은 실제 지역 복원과 지리 정합에 필요한 추가 입력을 설명한다. [카카오맵 공식 제공 기능](https://developers.kakao.com/docs/ko/kakaomap/common)은 지도 표시·정적 지도·좌표 조회이며, 거리 사진을 추출해 재구성 자산으로 배포하는 입력 계약을 제공하지 않는다.
