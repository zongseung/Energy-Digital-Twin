# 제주 에너지 디지털 트윈 웹디자인 개편 기획서

작성일: 2026-09-30 · 버전: 0.1 · 상태: 검토용 제안

대상: 현재 `http://localhost:8080/`의 탐라–한림 통합 3D 화면.

**지도를 화면 전체에 펼치고, 시설을 선택했을 때 해당 시설의 정보·가동 상태·주변 기상을 보여준다.** 기본 화면의 긴 사이드바와 수급 대시보드는 접고, 이동·회전·확대를 지도 위에서 직접 조작한다.

이 문서는 디자인 기획 산출물이다. 아래 화면·동작·수치는 제안이며, 개편 화면이 이미 구현되었다는 의미가 아니다. 기존 R&D 기획서의 연구 범위나 실제 시설 좌표를 변경하지 않는다.

## 1. 요구와 설계 기준

| 사용자 요구 | 설계 결정 | 성공 기준 |
|---|---|---|
| 지도를 최대한 보여주기 | 상시 사이드바 제거, 전체 폭 지도, 작은 도구만 표시 | 초기 화면에서 지도 높이가 화면의 약 90%를 차지한다 |
| 클릭하면 정보와 가동 상태 보기 | 선택한 시설의 상세 패널을 즉시 열기 | 시설명·가동 상태·실측 출력·자료 시각이 패널 첫 화면에 보인다 |
| 마우스 휠과 이동을 자유롭게 하기 | 커서 중심 확대·축소, 지면 이동, 회전, 짧은 관성 | 입력 지점 주변을 계속 보면서 탐색하며, 드래그가 선택으로 오인되지 않는다 |
| 우선 디자인 기획서 작성 | 구조·와이어프레임·조작·상태·반응형·검수 기준 제시 | 문서만 보고 기본 화면과 시설 선택 후 화면을 구분할 수 있다 |

현재 구현된 한 구역과 기존 영상·지형·3D 시설을 사용한다. 제주 전역으로 화면 범위를 확장하거나 시설 위치를 보기 좋게 재배열하지 않는다. 주요 사용 장면은 지역 에너지 시설 탐색과 공모전 시연으로 가정한다.

## 2. 현재 화면에서 확인한 문제

현재 [화면 캡처](../../../.omo/evidence/real-weather/missing-display-panel-1280.png), `index.html`, `style.css`, `app.js`, `grid.js`, 기존 `DESIGN.md`를 확인했다.

| 현재 구조 | 사용자가 겪는 문제 | 개편 방향 |
|---|---|---|
| 왼쪽 약 300px의 상시 정보 영역 | 지도 폭을 줄이며 기상·레이어·설비 상세가 한 스크롤에 섞인다 | 기능별 도구와 선택 상세를 분리한다 |
| 기상과 긴 레이어 설명 뒤에 시설 상세 배치 | 시설을 클릭해도 해당 정보가 바로 보이지 않는다 | 시설명과 핵심 상태를 상세 패널 맨 위에 둔다 |
| 지도 위에 시점 버튼 11개를 나열 | 첫 화면부터 조작 요소가 시선을 차지한다 | 전체 보기·방위·확대·축소를 남기고 나머지는 시점 메뉴로 묶는다 |
| 하단 수급·과거·시나리오 영역 상시 표시 | 지도 높이가 줄고 지역 집계와 개별 시설 정보의 구분이 약해진다 | 기존 기능을 ‘지역 분석’ 도구 안에 옮긴다 |
| 모바일에서 지도 뒤로 긴 본문이 이어짐 | 지도를 조작하다 정보를 찾으려면 페이지를 오가야 한다 | 지도를 유지하면서 아래에서 상세 시트를 연다 |
| OrbitControls 기본 조작 사용 | 왼쪽 드래그가 회전이며, 커서 중심 확대와 관성이 설정되지 않았다 | 지도 탐색에 맞는 버튼·터치 매핑과 카메라 갱신을 설계한다 |
| 터빈 회전 시연과 풍속 기반 추정 출력 제공 | 회전 모습을 실제 가동 상태로 오해할 수 있다 | 실측 상태와 시연·추정값을 다른 항목으로 표시한다 |

## 3. 구성안 비교와 추천

| 안 | 구성 | 장점 | 제약 |
|---|---|---|---|
| **A. 전체 지도 + 선택 상세 패널 — 추천** | 기본은 지도, 클릭 시 우측 상세, 모바일은 아래 시트 | 지도 면적과 선택한 시설의 맥락을 함께 유지한다 | 패널에 가려지는 위치와 휠 이벤트를 세심하게 처리해야 한다 |
| B. 접히는 목록 + 지도 + 상세 | 목록을 펼쳐 탐색하고 별도 상세를 연다 | 시설을 순서대로 비교하기 쉽다 | 여러 패널이 동시에 열리면 지도를 많이 가린다 |
| C. 지도 + 고정 상태 대시보드 | 지도와 주요 지표를 계속 나란히 보여준다 | 수치 모니터링에 적합하다 | ‘지도를 최대한 두기’라는 이번 요구에 덜 맞는다 |

A안을 기준으로 기획한다. 시설 목록은 필요할 때 여는 보조 도구로 제공하고, 첫 화면에서 특정 시설을 자동 선택하지 않는다.

## 4. 데스크톱 화면 구성

### 4.1 기본 화면

```text
┌─────────────────────────────────────────────────────────────┐
│ 탐라–한림 · 에너지 지도                 최신 보기   도움말   │
├─────────────────────────────────────────────────────────────┤
│ [시설]                                          [방위 N]    │
│ [레이어]                                                   │
│ [기상]                                                     │
│ [지역 분석]                                                │
│                                                            │
│                  현재 구역의 3D 지도                        │
│           풍력 · 태양광 · 송전선 · 변전소                    │
│                                                            │
│                                             [＋]           │
│                                             [－]           │
│ [지도 범례]                         [전체 보기] [시점]       │
├─────────────────────────────────────────────────────────────┤
│ 최신 보기 · 기상 갱신 상태 · 자료 출처                       │
└─────────────────────────────────────────────────────────────┘
```

상단 56px, 하단 상태 줄 28px, 나머지는 전체 폭 지도다. 1280×900 화면에서는 지도 캔버스가 1280×816, 화면 면적의 약 90.7%다. 이는 **캔버스 영역** 기준이며, 그 위에 겹치는 도구의 면적은 포함한다. 기본 화면에서 도구에 가리지 않는 지도 면적은 전체 화면의 85% 이상을 목표로 한다.

지도는 `100dvh` 안에 고정한다. 페이지 전체의 세로 스크롤은 만들지 않는다. 초기 시점은 풍력 배열과 육지를 함께 보여주는 기존 구역 시점을 사용한다.

### 4.2 시설을 선택한 화면

```text
┌─────────────────────────────────────────────────────────────┐
│ 탐라–한림 · 에너지 지도                 최신 보기   도움말   │
├───────────────────────────────────────┬─────────────────────┤
│ [시설]                                │ 탐라 해상풍력 01 [×]│
│ [레이어]                              │ 풍력 · 선택한 시설  │
│ [기상]                                │                     │
│ [지역 분석]                           │ 가동 상태: 확인 불가│
│                                       │ 실측 출력: —        │
│        선택 시설 표시                 │ 계측 시각: —        │
│        + 이름 + 선택 기호             │ 개별 계측 미연결    │
│                                       │                     │
│        지도를 계속 이동·확대 가능     │ [가까이 보기]       │
│                                       │                     │
│                                       │ 인근 관측소 / 거리  │
│                                       │ 풍속 · 기온 · 습도  │
│                                       │ 강수 · 일사량       │
│                                       │                     │
│                                       │ 제원 · 출처 펼치기  │
├───────────────────────────────────────┴─────────────────────┤
│ 최신 보기 · 기상 갱신 상태 · 자료 출처                       │
└─────────────────────────────────────────────────────────────┘
```

위 우측 영역은 지도 위에 겹치는 패널이다. 지도 캔버스의 크기는 바뀌지 않는다. 패널 폭은 360px 이하이며 1280px에서 가리지 않는 가로 폭을 약 70% 이상 유지한다. 클릭한 시설이 패널 아래에 가려질 때만 최소한의 카메라 이동으로 드러낸다.

일반 클릭은 상세를 열며 현재 확대율과 시점을 유지한다. ‘가까이 보기’를 눌렀을 때 시설 근접 시점으로 이동한다. 패널을 닫으면 원래 카메라를 유지하고 선택 표시를 지운다.

## 5. 지도 위 도구와 정보 배치

| 요소 | 기본 표시 | 열었을 때 내용 |
|---|---|---|
| 시설 | 이름 있는 작은 버튼 | 현재 구역의 시설 검색·종류 필터·목록. 목록 선택도 지도 클릭과 같은 상세를 연다 |
| 레이어 | 작은 버튼 | 풍력·PV·송전·변전소 / 영상·지형·건물·도로·식생 그룹. 긴 근거 설명은 항목별 펼치기 |
| 기상 | 작은 버튼 | 현재 기준 위치의 관측소·거리·풍속·기온·습도·강수·일사량·관측 시각. 전체 관측소는 별도 펼치기 |
| 지역 분석 | 작은 버튼 | 기존 제주 전체 수급·과거 재생·시나리오. ‘제주 전체 집계’ 제목을 유지한다 |
| 방위·확대·축소·전체 보기 | 지도 가장자리의 고정 도구 | 방위 초기화, 단계 확대·축소, 현재 구역 전체 시점 복원 |
| 시점 | 작은 메뉴 버튼 | 기존 풍력·해안, 지형, 마을, 바다, 선로, 태양광 시점 |
| 지도 범례 | 한 줄, 펼치기 가능 | 시설 종류와 계측 상태의 기호를 구분해 설명한다 |
| 자료 출처 | 하단 짧은 링크 | 실제 위치·영상·고도, 추정 형상, 촬영일 미확인 등의 상세 근거 |

시설·레이어·기상·지역 분석 중 보조 패널은 한 번에 하나만 연다. 시설을 선택하면 보조 패널을 닫고 시설 상세를 연다. 상세가 열린 상태에서 보조 도구를 누르면 선택 표시는 유지하되 상세를 그 도구로 대체하고 ‘선택 시설 정보로 돌아가기’를 제공한다. 여러 큰 패널을 겹치지 않는다.

시설을 선택하지 않은 기상 화면의 기준은 ‘구역 기준점’으로 명시한다. 선택 후에는 시설 위치 기준 인근 관측을 보여주며, 관측소가 시설 현장 계측이라는 표현을 쓰지 않는다.

## 6. 시설 상세 정보의 우선순위

첫 화면에는 **시설명 → 실측 가동 상태 → 실측 출력·계측 시각 → 가까이 보기 → 주변 기상** 순서로 배치한다. 시설 제원과 긴 출처는 아래에서 펼친다. 기상·출처 설명이 가동 상태보다 먼저 나오지 않도록 한다.

| 선택 대상 | 기본 정보 | 현재 표시 가능한 운전 정보 |
|---|---|---|
| 풍력 | 시설 ID·위치·공개 제원·형상 근거 | 실측 상태/출력은 확인 불가. 기존 풍속 기반 추정 가능 출력과 회전 시연은 별도 표시 |
| 태양광 | 등록 시설명·용량 kW·자료 기준일·배치 근거 | 실측 출력·가동 상태·일사 관측 미연결을 표시 |
| 변전소 | 시설명·전압·원천 위치·형상 근거 | 실측 부하·가동 상태·전기적 연결 확인 불가 |
| 송전선·케이블 | 경로 ID·종류·전압·경로 근거 | 전력 흐름·부하율 확인 불가. 장식용 흐름 화살표를 만들지 않는다 |
| 일반 건물 | 원천 ID·높이 근거·지붕 영상·추정 형태 | 에너지 설비의 가동 상태 항목을 붙이지 않는다 |

## 7. 가동 상태와 데이터 상태를 구분하는 규칙

**지금 확인할 수 있는 것은 시설 위치·일부 제원·주변 기상·제주 집계이며, 개별 설비의 실측 운전 상태는 아니다.** 첫 개편에서도 상태 항목은 제공하되 현재 시설에는 ‘확인 불가 · 개별 계측 미연결’을 표시한다.

| 실측 가동 상태 | 표시 조건 | 화면 표현 |
|---|---|---|
| 가동 중 | 식별된 해당 설비의 유효한 최신 운전 계측이 가동을 명시 | 상태 기호 + ‘가동 중’ + 계측 시각 |
| 정지 | 유효한 최신 운전 계측이 정지를 명시 | 상태 기호 + ‘정지’ + 계측 시각 |
| 점검 | 원천에서 점검 상태를 제공 | 상태 기호 + ‘점검’ + 계측 시각 |
| 이상 | 원천에서 이상·알람을 제공 | 상태 기호 + ‘이상’ + 원천 설명 |
| 확인 불가 | 미연결·결측·지연·원천에 상태 항목 없음 | 중립 기호 + 이유. 과거 상태가 있으면 ‘마지막 확인 상태’로만 표시 |

통신 연결/재연결은 위의 운전 상태와 다른 항목이다. API나 WebSocket이 연결되었다는 이유로 시설을 ‘정상’ 또는 ‘가동 중’으로 칠하지 않는다. 출력 0만으로 정지·점검·고장을 판정하지 않는다.

모델 추정 출력에는 항상 ‘추정 가능 출력’을 붙인다. 회전 시연을 켜도 실측 상태는 바뀌지 않는다. 지도 기호의 시설 종류 색과 운전 상태 기호도 분리하며, 상태는 색뿐 아니라 문구·모양으로 식별한다.

## 8. 기상 정보 디자인

시설 상세의 ‘주변 기상’은 표의 가로 스크롤을 요구하지 않는 두 열의 항목 목록으로 제공한다.

| 항목 | 단위와 표기 | 결측·지연 처리 |
|---|---|---|
| 풍속·풍향 | m/s · 바람이 불어오는 방위, 10분 평균 | 바람 상태를 따로 표시하며 기온 상태와 섞지 않는다 |
| 기온 | °C | 0°C는 유효값, 결측은 — |
| 습도 | % | 유효값과 결측 구분 |
| 최근 1시간 강수량 | mm · 이전 60분 누적 | 0mm와 결측 구분, mm/h로 바꾸지 않는다 |
| 일사량 | — · 일사 관측 미연결 | 현재 AWS 원천에 없음. 0이나 추정값으로 채우지 않는다 |
| 관측소·거리·관측 시각 | 시설에서의 거리 km, KST | 시설 현장값과 인근 관측값을 구분한다 |

지연된 관측은 마지막 값 옆에 ‘지연’과 원천 시각을 붙인다. 미연결은 ‘일사 관측 미연결’, 연결 실패는 ‘관측을 가져오지 못함’으로 구분한다. 짧은 안내가 항목 바로 옆에 보여야 한다.

현재 과거 재생은 제주 집계 범위다. 과거 집계를 재생할 때 시설 상세에 현재 기상을 함께 보여주면 ‘현재 기상’으로 명시하고, 과거 개별 운전 데이터가 있는 것처럼 회전이나 상태를 재생하지 않는다.

## 9. 마우스·휠·터치 조작

| 입력 | 제안 동작 | 세부 규칙 |
|---|---|---|
| 왼쪽 클릭 / 한 번 탭 | 시설 선택 | 실루엣·표식 선택 시 상세 열기. 빈 지도 클릭은 상세 닫기 |
| 왼쪽 드래그 | 지도 이동 | 지면에 평행한 이동. 누른 곳이 손을 따라오도록 처리 |
| 오른쪽 드래그 | 시점 회전·기울기 | 지도 안에서만 기본 문맥 메뉴 방지. 수평 회전 360° 허용 |
| Shift + 왼쪽 드래그 | 시점 회전·기울기 | 오른쪽 버튼을 쓰기 어려운 환경의 대체 조작 |
| 마우스 휠 / 트랙패드 스크롤 | 커서 중심 확대·축소 | 작은 입력은 작은 변화, 연속 입력은 즉시 이어짐. 입력마다 별도 카메라 애니메이션을 쌓지 않는다 |
| 두 번 클릭 | 해당 시설 가까이 보기 | 시설이 있는 경우만 근접 이동. 일반 선택과 구분 |
| 터치 한 손가락 드래그 | 지도 이동 | 탭과 이동 구분 |
| 터치 두 손가락 | 핀치 확대·축소 + 이동 | 회전은 명시적인 시점 도구로도 제공 |
| 확대·축소 버튼 | 단계 확대·축소 | 마우스 휠을 사용하지 않는 대체 수단 |
| 방위 버튼 / 전체 보기 | 북쪽 정렬 / 구역 시점 복원 | 현재 선택을 유지하면서 탐색 시점을 복원 |
| Esc | 가장 위의 패널 닫기 | 검색·메뉴를 먼저 닫고, 다음 입력으로 상세 닫기 |

### 카메라가 자유롭게 움직이되 길을 잃지 않는 기준

- 확대 중심은 커서 방향의 유효한 지면·해수면 기준점이다. 하늘·수평선처럼 교점이 안정적이지 않으면 현재 탐색 중심으로 확대한다.
- OrbitControls의 기존 `zoomToCursor`를 우선 사용한다. 현재 버전의 기능만으로 위 기준을 충족하는지 확인하고, 필요한 경우에만 제한된 지면 교점 처리를 보완한다.
- 이동·회전 후 짧게 감속하되, 새 입력이 들어오면 즉시 반응한다. 휠 입력에 긴 이동 애니메이션을 붙이지 않는다.
- 확대·축소 범위와 이동 중심은 현재 장면의 경계·시설 크기로 정한다. 지형 아래 진입, 시설 내부 관통, 구역을 잃을 정도의 무한 이동은 막는다. 실제 지형 높이를 고려한 충돌 보정이 필요하다.
- 드래그 이동량이 클릭 허용 범위 5px를 넘으면 시설을 선택하지 않는다. `pointercancel`과 다중 터치 이후에는 클릭 후보를 취소한다.
- 상세·목록·기상 표 위의 휠은 해당 영역의 스크롤이다. 지도 확대가 함께 실행되지 않게 한다. 투명한 전체 화면 레이어가 지도 입력을 가로막지 않게 한다.
- 지도 위에서만 필요한 기본 동작을 막는다. Ctrl/Command + 휠 등 브라우저 확대 접근성 조작은 보존한다.
- ‘가까이 보기’ 이동 도중 드래그·휠이 시작되면 자동 이동을 취소하고 사용자 입력을 우선한다.

## 10. 지도 선택 표시

멀리서는 시설별 표식을, 가까이서는 3D 설비 자체를 선택할 수 있다. 풍력·PV·변전소·선로의 기호를 다르게 하고, 겹치는 경우 클릭한 위치의 시설 후보 목록을 짧게 제공한다.

선택 시설에는 기호와 이름을 표시한다. 선로는 기존 선택 강조를 재사용하며, 시설은 별도의 선택 표식으로 위치를 명확히 한다. 마우스를 올릴 때는 이름과 ‘상세 보기’ 힌트만 표시하고 긴 정보 창은 열지 않는다. 터치와 키보드에서는 시설 목록이 같은 정보를 제공한다.

표식의 클릭 영역은 최소 44px를 확보한다. 풍력 배열 같은 밀집 구역은 이름이 서로 겹치지 않도록 선택·호버 시설을 우선 표시한다. 레이어를 끄면 해당 시설의 표식·목록·선택 대상도 사라지고, 숨겨진 시설의 상세는 닫는다.

## 11. 반응형 구성과 스크롤 책임

| 화면 폭 | 지도와 상세 | 도구 배치 |
|---|---|---|
| 1024px 이상 | 전체 지도 + 우측 최대 360px 상세 | 왼쪽 작은 도구, 우측 하단 지도 조작 |
| 768–1023px | 전체 지도 + 우측 최대 320px 상세 | 동일 구조, 상세 패널과 지도 조작이 겹치지 않도록 위치 조정 |
| 767px 이하 | 전체 지도 + 아래 상세 시트 | 주요 도구를 짧은 가로 줄에 배치. 제목·버튼이 넘치지 않게 재배치 |

모바일 기본 화면에서는 상세 시트를 닫는다. 시설 선택 시 지도 영역 높이의 약 40%까지 시트를 열고, ‘펼치기’로 최대 70%까지 확장한다. 축소·닫기 버튼을 항상 제공하며 시트 손잡이의 드래그만으로도 높이를 바꿀 수 있다. 본문 스크롤과 손잡이 드래그를 구분한다.

```text
┌───────────────────────────┐
│ 탐라–한림       [도움말]   │
│ [시설] [레이어] [기상] [⋯]│
│                           │
│          3D 지도          │
│        선택 시설 표시     │
│                    [＋]   │
│                    [－]   │
├───────────────────────────┤
│ [펼치기]              [×] │
│ 탐라 해상풍력 01          │
│ 가동 상태: 확인 불가      │
│ 실측 출력: —              │
│ 개별 계측 미연결          │
│ [가까이 보기]             │
│ 주변 기상 · 제원          │
└───────────────────────────┘
```

스크롤 책임은 지도와 각 패널로 나눈다. 지도는 페이지 스크롤을 하지 않으며 지도 조작만 받는다. 상세 패널은 고정 제목 아래 본문 하나만 세로 스크롤한다. 보조 도구도 본문 하나를 스크롤한다. 전체 관측소 표의 가로 스크롤은 그 표 내부로 한정한다. 패널의 끝에서 스크롤이 지도 조작으로 넘어가지 않게 한다.

## 12. 시각 디자인과 제안 토큰

기존 실제 영상·지형을 주 시각 요소로 두고, 도구와 패널에는 차분한 차콜 표면을 사용한다. 제주의 해안·시설이 잘 보이도록 화면 전체를 어둡게 덮는 막은 사용하지 않는다. 지도 위 정보 표면에는 얕은 그림자를 주어 지형과 분리하되, 본문 뒤로 영상이 비쳐 읽기 어려운 강한 투명 효과는 피한다.

| 항목 | 제안 |
|---|---|
| 기본 색 | 기존 `--bg`, `--surface`, `--surface-raised`, `--text`, `--muted` 재사용 |
| 선택 색 | 기존 `--accent` 재사용. 면의 명도 변화와 선택 기호로 표시 |
| 시설 종류 색 | 기존 송전·PV·변전소 등의 범례 색 유지. 가동 상태 색과 구분 |
| 간격 | 기존 4/8/12/16/20/24px 간격 체계 |
| 글꼴 | 기존 한글 시스템 글꼴. 숫자는 tabular-nums |
| 본문·기상값 | 14px 이상, 주요 시설명 20px, 핵심 숫자 20–28px |
| 보조 설명 | 12px, 긴 설명은 펼치기로 제공 |
| 조작 크기 | 최소 44×44px, 도구 이름과 키보드 초점 표시 |
| 모서리 | 기존 작은 도구 4px, 패널 8px 체계 |
| 새 크기 토큰 | 상세 360px, 중간 화면 상세 320px, 상태 줄 28px |
| 동작 토큰 | 버튼 피드백 120ms, 패널 진입·퇴장 180ms, 명시적 근접 이동 350ms, 카메라 감쇠 초기값 0.08 |

새 토큰은 구현 전에 기존 `renderers/twin/DESIGN.md`에 반영한다. 감쇠와 확대 민감도는 마우스·트랙패드·375/768/1280px 실기 검수에서 조정하는 초기값이다. 패널은 transform/opacity로 전환하고 열리고 닫힐 때 지도 크기를 애니메이션하지 않는다.

`prefers-reduced-motion`에서는 자동 카메라 이동을 즉시 전환하고 관성을 끄며, 패널 이동 대신 짧은 명도 전환을 쓴다. 실제 상태 문구와 선택 결과는 항상 남는다.

## 13. 접근성·오류·연결 상태

지도 클릭의 모든 시설은 이름 있는 목록 버튼으로도 선택할 수 있다. 지도 탐색에 드래그만 요구하지 않고 시점·회전·확대·축소 버튼을 제공한다. 검색·메뉴는 키보드로 조작하며, 상세를 열면 제목 또는 닫기 버튼으로 초점을 보내고 닫을 때 선택 목록 버튼이나 지도 조작 영역으로 돌려준다.

시설 상세는 비모달 정보 패널이다. 초점을 강제로 가두지 않으며 상세가 열려도 지도를 조작할 수 있다. 모바일 전체 화면을 덮는 별도 모달은 이번 구성에 넣지 않는다.

| 상태 | 표시와 유지할 기능 |
|---|---|
| 지도 로딩 | 지도 영역에 로딩 안내. 기상·시설 목록은 준비되는 대로 별도 제공 |
| 지도 로드 실패·WebGL 중단 | 지도 영역에 재시도/복구 안내. 텍스트 시설 정보와 기상은 유지 |
| 시설 계측 미연결 | 해당 상세에 확인 불가와 이유. 지도 자체는 오류 화면으로 바꾸지 않는다 |
| 기상 결측·지연 | 항목별 — 또는 마지막 값·시각·지연 표시 |
| API/WS 연결 실패 | 해당 데이터의 재연결 상태. 시설 운전 이상과 구분 |
| 검색 결과 없음 | 입력어와 결과 없음 표시, 필터 초기화 버튼 |
| 전부 숨긴 시설 레이어 | 지도 지형은 유지하고 시설 레이어 켜기 안내 |

## 14. 구현 시 재사용할 부분과 변경 범위

현재 화면은 native HTML/CSS/ES modules + Three.js 0.180.0이다. 기존 GLB·GIS·원천 좌표·시설 레코드·기상 API·WS·지역 분석 기능을 재사용한다. 새로운 UI 프레임워크나 지도 엔진 도입을 전제하지 않는다.

| 파일 | 설계가 요구하는 변경 |
|---|---|
| `renderers/twin/DESIGN.md` | 승인된 화면 구조·상태·토큰·스크롤·조작 계약 반영 |
| `renderers/twin/index.html` | 전체 지도 셸, 도구, 선택 상세, 모바일 시트로 정보 재배치 |
| `renderers/twin/style.css` | 지도 우선 배치, 패널·시트·반응형 스타일. 공용 site 화면에 영향이 없도록 twin 범위에서 처리 |
| `renderers/twin/app.js` | 선택/닫기/도구 상태, 포커스, 카메라 입력과 감쇠 렌더 루프, 기존 기상·분석 표시 연결 |
| `renderers/twin/grid.js` | 선택 표식과 레이어별 선택 가능 여부. 기존 시설 ID·좌표·형상·행 정보를 보존 |

특히 `enableDamping`만 켜는 변경으로 끝내지 않는다. 현재 `change` 이벤트 중심 렌더 구조에 맞춰 이동 중 `controls.update()`를 프레임별로 호출하고, 멈추면 루프를 중단해야 한다. 회전 시연 루프와 중복 렌더를 만들지 않고 숨긴 탭·WebGL 중단 시 멈춘다.

개별 가동 상태 API와 일사 관측 연동은 별도 데이터 작업이다. 이 디자인 개편만으로 해당 실측 자료가 생기지 않는다. 데이터가 추가되기 전에도 미연결 상태의 화면은 완결되게 제공한다.

## 15. 권장 적용 순서

1. **지도 면적과 화면 구조:** 전체 지도, 작은 도구, 기존 분석 접기, 로딩/실패 상태.
2. **시설 선택 상세:** 같은 ID의 지도·목록 선택, 핵심 정보 우선 배치, 닫기·레이어 숨김·포커스.
3. **탐색 조작:** 커서 중심 휠, 이동·회전 매핑, 감쇠, 경계·지형 충돌·입력 중단 처리.
4. **모바일 상세:** 지도 유지, 아래 시트, 확대·축소·시점 대체 조작, 스크롤 분리.
5. **통합 검수:** 기존 기상·지역 분석·회전 시연·정직한 상태 표기가 모두 유지되는지 확인.

이는 적용 우선순위다. 이번 문서 작성과 실제 구현을 구분하며, 개별 계측 미연결 상태를 가동 중으로 대체하는 단계는 없다.

|---|---|
| 1280×900 첫 진입 | 상세 자동 선택 없음. 지도 캔버스 약 90.7%, 기본 비가림 지도 면적 85% 이상 |
| 풍력/PV/변전소/선로 클릭 | 해당 시설명·실측 상태·출력·시각이 상세 첫 화면에 표시. 미연결 상태를 정확하게 표시 |
| 일반 건물 클릭 | 건물 근거 표시. 발전설비 가동 상태를 붙이지 않음 |
| 다른 시설 연속 선택 | 패널 내용을 같은 시설 ID로 갱신. 이전 시설 수치나 관측소가 남지 않음 |
| 시설 선택 후 지도 이동 | 지도 입력 유지. 상세 패널이 카메라를 계속 강제 복귀시키지 않음 |
| 지도 휠 / 패널 휠 | 지도에서는 확대, 패널에서는 본문 스크롤. 두 동작이 함께 발생하지 않음 |
| 커서 중심 확대 | 안정적인 지면 교점에서 표적이 커서 근처에 유지. 수평선·교점 없음에서도 카메라 좌표가 유한 |
| 빠른 휠·드래그·반대 방향 입력 | 즉시 반응. 이동 애니메이션 대기열이나 드래그 후 잘못된 선택 없음 |
| 근접 이동 도중 드래그 | 자동 이동 중단, 사용자 입력으로 전환 |
| 극단적 확대·이동 | 지형 아래 진입·시설 관통 방지. 전체 보기로 항상 복귀 가능 |
| 선택한 시설 레이어 끄기 | 표식·목록·선택 대상에서 제외하고 상세 닫기 |
| 375/768px 및 낮은 높이 화면 | 전체 페이지 가로 넘침 없음. 시트·패널·지도 조작이 겹치지 않고 닫기 가능 |
| 키보드·동작 줄이기 | 시설 선택과 상세 읽기 가능. 초점 복귀·Esc 동작, 관성/자동 이동 축소 |
| 통신 장애·부분 결측·지연 | 데이터별 상태 유지. 기상 결측을 0, 연결 성공을 시설 가동으로 오표시하지 않음 |
| 과거 집계·시나리오 | 제주 전체 범위 표시 유지. 현재 기상을 과거 개별 운전 자료로 표현하지 않음 |
| 탭 숨김·카메라 정지 | 불필요한 카메라 렌더 루프 중단. 복귀 후 조작과 데이터 갱신 정상 |

검수 시 실제 `localhost:8080`에서 마우스·휠·터치/키보드를 구동하고 375/768/1280px 화면 증거를 남긴다. 첫 버전의 ‘가동 상태 확인 불가’와 ‘일사 관측 미연결’은 현재 데이터 조건에 맞는 결과다.

## 17. 참고와 근거

- [현재 화면의 디자인 계약](../../../renderers/twin/DESIGN.md), [화면 구조](../../../renderers/twin/index.html), [선택·카메라·기상 처리](../../../renderers/twin/app.js), [시설·레이어 처리](../../../renderers/twin/grid.js).
- [실제 화면 증거](../../../.omo/evidence/real-weather/missing-display-panel-1280.png), [localhost 기상 표시 검증](../../../.omo/evidence/real-weather/missing-display-qa-1280.json). 기획 도식의 구현 완료 증거로 사용하지 않는다.
- 현재 설치된 `three@0.180.0`의 `OrbitControls.js`에서 `zoomToCursor`, `screenSpacePanning`, `enableDamping`, `mouseButtons`, `touches`와 수평선 부근 확대 처리를 확인했다.
- [StyleGallery overlay-stack](https://github.com/changeroa/StyleGallery/blob/main/patterns/overlay-exception/overlay-stack.md): 전체 지도와 도구가 같은 영역에 겹치는 배치의 참고. 패널 내부 스크롤은 본 기획서에서 별도로 정의한다.
- [StyleGallery supporting-pane](https://github.com/changeroa/StyleGallery/blob/main/patterns/split-sidebar/supporting-pane.md): 주 작업과 선택 정보의 관계 참고. 균등 열 배치는 채택하지 않는다.
- [beui drawer 원천](https://beui.dev/r/drawer/raw): 패널 진입 방향·Esc·동작 줄이기 처리 참고. React 구현·모달 배경막·초점 가두기는 채택하지 않는다.
