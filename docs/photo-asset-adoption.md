현재 사진이 없는 것은 아니다. **공개 사진만으로 연속적인 도로 수준 3D 현장을 복원하거나, 단일 이미지 GLB의 미터 크기·좌표를 자동으로 확정할 수 없는 상태**다. Naver 거리 사진을 재구성 원본으로 자동 수집·재배포하는 경로도 확인되지 않았다. [Wikimedia Commons 후보 목록](https://commons.wikimedia.org/wiki/Category:Sinchang_Windmill_Coastal_Road), [신창 09 사진](https://commons.wikimedia.org/wiki/File:Sinchang_Windmill_Coastal_Road_09.jpg), [VisitJeju 신창 소개](https://www.visitjeju.net/u/5Sh)를 출처별로 구분한다.

첫 실제 자산을 넣으려면 **한 지물 또는 시설의 동일성**을 원천 시설 ID나 새 지물 좌표와 대조하고, 재구성·배포가 가능한 원본 사진, 사진 속 확인 가능한 기준 길이의 출처, 모델상의 같은 두 점, 기준점 및 방향의 근거를 확보해야 한다. `photo_assets.py`는 이 근거와 원본·GLB 해시를 검증한 정적 설비만 등록한다. 길이 하나를 맞춰도 가려진 후면이나 다른 모든 치수가 실측이 되는 것은 아니다. 풍력기 교체에는 회전자 pivot 검증이 추가로 필요하다.

신창 **도로 구간 전체**를 실제 현장처럼 만들려면 동일 구간을 여러 방향에서 중첩 촬영한 사진(또는 영상에서 추출한 프레임), 재사용 권리, 촬영 위치·방향 정보와 몇 개의 측지 기준 또는 검증 가능한 현장 치수가 필요하다. 영상 파일 자체가 필수는 아니며 겹치는 다중시점 사진도 된다. [OpenDroneMap 촬영 가이드](https://docs.opendronemap.org/flying/)와 [GCP 가이드](https://docs.opendronemap.org/gcp/)가 중첩 촬영 및 지리 정합 입력을 설명한다. 측량 자료가 없는 현재는 공개 DSM과 GIS에 맞추되 정확도는 별도 검증 전까지 추정으로 표시한다. 도로 전 구간을 덮는 이 입력은 아직 확보되지 않았다.

등록 파일 `var/rendering/photo-assets/manifest.json`은 없거나 `{"schema_version":1,"assets":[]}`로 유지한다. 신창09의 등대 GLB를 해상 풍력기로 등록하거나, 합성 테스트 박스를 운영 장면으로 복사하지 않는다.

## 구현 및 검증 결과

GPU 서버 `feat/photo-scene`에서 기존 추론 GLB 검사 함수를 재사용해 외부 텍스처·buffer URI를 거부한다. 자산과 텍스처가 같은 GLB 해시에 묶인다. 원본 법선, 사진 재질·UV, 기준점·균일 축척·yaw를 유지하며, 시설 동일성·기준 길이·방향의 근거가 필수다. 웹 상세에는 사진 출처와 확인된 길이, 나머지 형상의 추정 상태를 표시한다.

`uv run renderers/twin/test_photo_assets.py`가 통과했다. 잘못된 hash·근거 누락·중복 ID·풍력/선로 등록·비유한 축척·외부 리소스를 거부하고, 기준점이 원점에서 벗어난 90도 회전의 텍스처 자산을 같은 시설 노드에 배치한다. 사진 재질의 픽셀·UV·원본 법선과 기준 길이를 직접 대조한다. 검증 실패를 강제로 일으킨 경우에도 기존 장면·manifest가 보존된다.

등록이 없는 최종 빌드는 15시설·10회전자·623건물을 유지하며 GLB SHA-256이 기존과 같은 `5c243005a6dd64b2bafe9097aa7cb3d0d655f65881dec68770b6210fa70992d6`다. Chromium 375/1280px에서 변전소 선택, 가로 넘침 없음, 페이지 오류 없음, 테스트 응답의 사진 출처·길이 표시를 확인했다. Omniverse GPU1에서는 합성 자산을 포함한 GLB의 15시설 기준점·기준 길이와 1m/Y-up을 검사하고, USD 저장·재열기 및 1600×1000 PNG 생성을 확인했다. 이 검사는 실제 제주 도로 형상의 복원 성공을 뜻하지 않는다.

CLI는 임시 디렉터리에서 빌드·검증을 끝낸 뒤 출력 파일을 교체한다. Docker의 디렉터리 마운트를 유지하기 위해 파일별로 교체하고 manifest를 마지막에 쓴다. 여러 파일을 읽는 동시 클라이언트까지 하나의 원자적 스냅샷으로 묶지는 않는다. 그런 배포가 필요해지면 버전별 자산 URL이 필요하다.
