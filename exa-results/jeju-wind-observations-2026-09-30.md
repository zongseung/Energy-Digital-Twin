# 제주 신창/탐라 인근 실측 바람 데이터 조사

조사 기준: 2026-09-30 KST. 런타임 시계 `2026-09-29 17:32:01 UTC + 09:00 = 2026-09-30 02:32:01 KST`를 기준으로 원본 응답의 신선도를 확인했다. Exa Search 스킬로 5개 검색 × 5개 결과 = **25개 검색 결과**를 검토했고, 공식 기상청 자료만 구현 근거로 사용했다. 검색 결과/Exa fetch의 캐시는 현재 관측으로 취급하지 않았다.

## 바로 구현 가능한 경로

키 없이 **기상청 날씨누리 공개 JSON**을 읽을 수 있다. 고산 관측소(185)는 대상 좌표 `33.34303, 126.17217`에서 직선거리 약 **5.540 km**다.

```text
GET https://www.weather.go.kr/w/observation/land/aws-obs-data.do?db=MINDB_01M&stnId=185&config=full
```

2026-09-30 02:33:39 KST의 직접 HTTP 요청에서 200 응답을 받았고, 최신 관측은 02:28 KST였다(수신 시 약 5분 39초 전). 인증키·쿠키·브라우저 자동화가 필요하지 않았다. 이 경로는 [공개 페이지](https://www.weather.go.kr/w/observation/land/aws-obs.do)의 [공식 클라이언트 JS](https://www.weather.go.kr/w/resources/js/app-2021/app-obs-climate-land-aws-obs.js)가 사용하는 GET 경로다. 문서화된 APIHub 계약과는 별개의 웹사이트 내부 공개 경로이므로 형식 변경 가능성은 있다.

실제 응답 일부:

```json
{
  "dataTm": "202609300228",
  "stnId": "185",
  "stnInfo": {"awsId": "185", "nameKo": "고산", "lat": "33.29382", "lon": "126.16283", "height": "71"},
  "windUnit": "m/s",
  "tm": "2026.09.30 02:28",
  "items": [{
    "awsStnId": 185,
    "tm": "202609300228",
    "awsWs10": "3.5",
    "awsWd10": "북동",
    "awsWs1": "2.9",
    "awsWd1": "북동",
    "awsTroblKnd": ""
  }]
}
```

`items`는 여러 분의 시계열이다. 받은 표본에서는 최신순이었지만 구현은 지점번호와 유효한 시각으로 최신 자료를 선택해야 한다. `dataTm`/루트 `tm`은 조회 기준이며 **실제 선택한 항목의 `tm`**을 관측 시각으로 기록한다. `%Y%m%d%H%M`을 KST (`UTC+09:00`)로 해석한다. 위 표본의 UTC 시각은 `2026-09-29T17:28:00Z`다.

| 필드 | 의미/검증 |
|---|---|
| `awsWs10` | 직전 10분 평균 풍속, m/s 문자열. 유한한 0 이상 숫자로 파싱 |
| `awsWd10` | 직전 10분 평균 풍향의 **16방위 한글 표기**. 정확한 수치 각도가 아님 |
| `awsWs1`, `awsWd1` | 직전 1분 평균 바람. 10분 자료와 섞지 않음 |
| `awsWss`, `awsWds` | 해당 1분의 순간 최대풍속과 그때 풍향. 평균풍속과 구별 |
| 루트 `windUnit` | `m/s` 확인. 항목별 `windUnit: null`은 실제 정상 응답에도 나타남 |
| `stnInfo` / 항목 `lat`, `lon` | 관측소 좌표. 터빈 좌표가 아님 |
| `awsTroblKnd` | 장애 상태. 공식 JS는 `장애`, `비장애중단`, `N/A`를 별도 처리 |

평균 정의와 매분/10분간격 표시 주기는 [기상청 도움말](https://www.kma.go.kr/wnuri_help/html/observation/aws-obs.jsp)에 명시되어 있다. `MINDB_01M`은 매분 표본이고 `awsWs10`은 매분 갱신되는 직전 10분 평균이다. 서비스 지연 약 5분은 이번 측정값이며 보장된 SLA가 아니다.

## 풍향, 결측, 정온 처리

풍향은 기상 관례에 따라 바람이 **불어오는 방향**이다. 16방위를 시계방향으로 매핑하면 `북=0°, 북북동=22.5°, 북동=45°, 동북동=67.5°, 동=90°, 동남동=112.5°, 남동=135°, 남남동=157.5°, 남=180°, 남남서=202.5°, 남서=225°, 서남서=247.5°, 서=270°, 서북서=292.5°, 북서=315°, 북북서=337.5°`다. 이 각도는 16방위 중심각이므로 UI에는 `북동 / 약 45°` 또는 `16방위 관측`으로 표시한다. 이동방향을 가리키는 화살표라면 `(fromDegrees + 180) % 360`을 사용한다.

검증 중 제주 송당(862), 어리목(753)의 실제 응답은 `awsWs10="0"`, `awsWd10="북"`이었다. **풍속 0일 때 북풍으로 표시하지 말고 방향을 무의미/null로 처리하고 화살표/풍향 추종을 멈춘다.** `정온` 같은 명시적 정온 표기도 방향 없음으로 취급한다.

숫자 필드의 `null`, 빈문자열, `.`, `-`, 숫자 파싱 실패, 음수, 비유한 수는 결측으로 취급한다. 공개 JSON의 바람 결측에 대한 공식 완전한 sentinel 목록은 확인되지 않았다. 음수 sentinel을 숫자 관측으로 받아들이면 안 된다. 실제 기존 표에서는 `.`, `&nbsp;`가 결측으로 쓰였다. `awsTroblKnd`의 장애/중단 항목은 채택하지 않는다. 빈 상태 문자열은 정식 QC 통과를 보장하지 않으므로 품질 표기는 **실시간 참조 자료, QC 상태 미제공**이 적합하다.

권장 구현 정책(기상청이 정한 규칙은 아님): 서버에서 60초 캐시, 짧은 HTTP timeout, 관측이 15분 이상 오래되면 stale 표기, 실패 시 마지막 값의 실제 관측시각 유지, 미래 시각/지점 불일치 거부. 최신 항목이 결측이면 오래된 유효 항목을 선택하더라도 그 나이를 노출한다.

## 정확한 소수점 각도가 꼭 필요한 경우

공식 기존 AWS 표는 숫자 풍향과 16방위를 함께 제공한다. [기존 화면](https://www.weather.go.kr/plus/land/current/aws_table_popup_jeju.jsp)의 [메뉴 JS](https://www.weather.go.kr/plus/land/current/aws_table_menu.jsp)에서 발견한 공개 경로:

```text
GET https://www.weather.go.kr/cgi-bin/aws/nph-aws_txt_min_cal_test?0&0&MINDB_01M&185&m&M
```

2026-09-30 02:35:10 KST 직접 요청 200. 페이지 기준시각 02:33의 선두 행들은 결측이었고, 최신 유효행은 다음과 같았다.

| 관측 KST | 10분 풍향 | 10분 풍속 | 1분 풍향 | 1분 풍속 |
|---|---:|---:|---:|---:|
| 2026-09-30 02:29 | 39.8° | 3.5 m/s | 48.3° | 3.2 m/s |
| 2026-09-30 02:28 | 37.8° | 3.5 m/s | 40.4° | 2.9 m/s |

02:28 값은 앞의 JSON 풍속 3.5/2.9 m/s와 일치했다. 응답은 JSON이 아닌 EUC-KR HTML이다. 각 유효 `<tr>`에는 16개의 `<td>`가 있으며 0부터 시작한 열번호는 `8=1분 각도, 9=1분 방위, 10=1분 풍속, 11=10분 각도, 12=10분 방위, 13=10분 풍속`이다. 시각은 행 첫 링크의 `stn_tm_select(...,202609300229)`에 들어 있다. 열 수·헤더·단위·지점 표제를 확인하고 행 단위로 결측을 거른 뒤 최신 행을 선택해야 한다. **페이지 상단 조회시각을 관측시각으로 사용하지 않는다.** 정밀 각도 요구가 없다면 JSON+16방위가 더 작은 구현이다.

## 인근 관측소와 위치 한계

[현재 제주 전체 JSON](https://www.weather.go.kr/w/observation/land/aws-obs-data.do?db=MINDB_01M&stnId=0&sidoCode=5000000000)으로 43개 지점 좌표를 받아 대상 위치와 haversine 거리를 계산했다. 02:34:28 KST 수신, 항목 관측시각 02:29 KST. 아래는 가까운 순이다.

| 관측소 | 번호 | 위도 | 경도 | 직선거리 |
|---|---:|---:|---:|---:|
| 고산 | 185 | 33.29382 | 126.16283 | 5.540 km |
| 낙천 | 990 | 33.31822 | 126.23050 | 6.081 km |
| 한림 | 779 | 33.39268 | 126.25809 | 9.703 km |
| 대정 | 793 | 33.24101 | 126.22626 | 12.408 km |

`한림=779`이며 `328=상예`다. `신창`이라는 별도 관측소는 이 공식 제주 목록에서 확인되지 않았다. 고산 좌표는 [공식 지점정보](http://minwon.kma.go.kr/main/obvStn.do), [현행 공개 지점 JSON](https://www.weather.go.kr/w/rest/zone/find/aws-stations.do?keyword=185)과 일치한다. 풍속계 지상높이 10m, 관측장 해발고도 약 71m는 공식 지점정보에 있다. [제주 관측환경](https://www.kma.go.kr/jeju/html/observation/observation_info.jsp)에서도 관측요소·위치가 확인된다.

이 자료는 현장 근처 지상 관측소의 바람이다. 해상 터빈 허브 높이의 바람, 실제 나셀 yaw, RPM, 출력/SCADA를 측정한 값이 아니다. 나셀을 이 풍향으로 움직이면 `인근 관측 풍향 기반 DEMO`로 표시해야 한다. 관측 풍속을 실제 로터 RPM으로 변환하는 근거는 없다.

## 문서화된 API와 인증

[기상청 APIHub AWS 매분자료 문서](https://apihub.kma.go.kr/apiList.do?seqApi=2&seqApiSub=239)의 공식 경로:

```text
https://apihub.kma.go.kr/api/typ01/cgi-bin/url/nph-aws2_min?stn=185&disp=1&help=1&authKey=YOUR_KEY
```

`tm1`, `tm2`는 KST, `tm2` 생략 시 현재시간, `stn`은 지점번호, `disp=1`은 쉼표구분, `help=1`은 필드설명 포함, `authKey`는 발급 인증키다. 실제 인증키 없이 요청한 결과는 **HTTP 401**이며 `유효한 인증키가 아닙니다.`였다. APIHub를 계약된 데이터 경로로 쓰려면 발급/활용신청이 필요하다. 승인 없는 키를 만들어내거나 다른 사람의 키를 쓰지 않았다. 분 자료 원문의 정확한 header/QC sentinel은 인증을 통과한 응답을 받지 못해 검증하지 않았다.

## 출처표시와 이용조건

표시는 `출처: 기상청 날씨누리 / 고산(185), 10분 평균, 관측시각 … KST`처럼 출처·지점·기간·시각을 함께 두고 공개 관측 페이지를 링크한다. 날씨누리는 실시간 자료를 참조용으로 제공하며 기상증명 같은 증빙자료로 사용할 수 없다고 안내한다.

[기상청 저작권 정책](https://www.weather.go.kr/kma/guide/copyright.jsp)은 기상청이 저작권 전부를 보유한 자료 중 공공누리 제1유형 표시 자료의 자유이용과 구체적 출처표시를 설명하며, 표시가 없는 자료의 사용은 담당자와 협의하도록 안내한다. **이 JSON 응답 자체에는 별도 라이선스 표시가 없었으므로 무제한 재배포 라이선스를 단정하지 않았다.** [공공데이터포털 지점정보 서비스](https://www.data.go.kr/data/15058846/openapi.do)는 출처표시 제1유형과 제3자 권리 포함을 명시한다. 이 문구를 별개의 웹사이트 바람 응답 전체에 자동 적용하지 않는다.

## 재현 자료

- `var/verification/weather/gosan-latest-sample.json`: 수신시각·URL·고산 최신 JSON 최소 표본.
- `var/verification/weather/gosan-data.json`: 원본 고산 시계열 JSON.
- `var/verification/weather/gosan-station.json`: 원본 지점 좌표 JSON.
- `var/verification/weather/jeju-data.json`: 43개 제주 지점 응답, 0풍속/북 표기 사례 포함.
- `var/verification/weather/legacy-gosan.txt`: 수치 각도가 든 원본 기존 HTML.
- `var/verification/weather/legacy-gosan-extract.json`: 기존 표 최신 유효행과 파싱한 16개 셀.
- `var/verification/weather/aws-client.js`: 공개 JSON 호출·장애 표시의 공식 코드 근거.

검색 캐시의 AWS 페이지는 2026-08-30 관측을 반환했으나, 같은 페이지를 직접 요청하면 2026-09-30 관측을 반환했다. Exa 검색은 경로 발견용이며 현재값 검증은 직접 HTTP 응답으로 수행했다.

## 구현 확대 후 위치 정정

사용자 요청으로 단일고산 대신 위 제주 전체 공개JSON을 매60초 한 번 수집하도록 확대했다. 현재43개 반환 지점을 모두 유지하고 바람 결측도 표시한다. 위5.540km는 장면 중심 기준이다. 실제 터빈10개의 원천좌표별로는5722/5723만 고산이 가장 가깝고,5724–5731은 낙천이 가장 가깝다. 전체행을 받아 시설별거리를 계산해야 이 차이를 반영할 수 있다. 추가 Exa 검색을 수행한 결과가 아니라 앞서 확인한 공식 전체응답과 기존 GIS 좌표의 직접 대조다.
