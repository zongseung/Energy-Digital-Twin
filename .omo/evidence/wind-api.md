# Jeju wind API evidence

- One background task fetches the KMA full-Jeju batch (`stnId=0&sidoCode=5000000000`) immediately and every 60 seconds. A shared HTTP client has an 8-second total timeout; the response body is limited to 1 MiB. `MissedTickBehavior::Skip` prevents catch-up bursts. Neither API route makes a source request.
- `GET /api/v1/jeju/wind/stations` returns `{source, source_url, received_at, poll_interval_seconds, stale_after_seconds, station_count, stations}`. Each station has the previous wind response fields and `station:{id,name,latitude,longitude}`. `GET /api/v1/jeju/wind` returns Gosan (185) from the same cache for compatibility, with its fixed 5.54 km distance from scene origin `(33.34303, 126.17217)`. The station list omits `distance_km` because distance depends on the selected facility.
- The parser verifies the root all-stations Jeju marker, region code, ID and `m/s` unit. Each station row is decoded independently; valid metadata (unique ID, nonempty name, finite coordinates inside the Jeju bounds) is retained even if wind is missing or disabled. Invalid metadata rows are skipped without dropping other stations. Duplicate rows with matching metadata use the newest valid item timestamp. Wind uses the item timestamp interpreted as KST, 10-minute average speed, and a 16-point compass center angle. Negative/nonfinite/missing speeds, nonempty or missing trouble flags, future timestamps over 60 seconds and invalid noncalm directions are excluded. Zero speed yields null direction.
- A valid batch updates station metadata and reading availability together. An invalid or missing station row retains any prior accepted observation but is marked stale; a new station with no usable wind is unavailable. A failed whole-batch fetch retains the previous cache and marks every observed station stale. Freshness requires a successful current row, observation age 0–900 seconds and receipt age 0–150 seconds. Flags include `qc_not_provided`, `station_data_missing`, `source_fetch_failed` and `source_delayed` when applicable. Both routes return HTTP 200 and `Cache-Control: no-store`.
- The data path is an internal public KMA website JSON route, not a documented API contract. These are nearby ground-station 10-minute means, not turbine hub wind, rotor RPM or SCADA. There is no historical store.

Verification: `src/weather_fixture.json` is a compact extraction of all 43 rows from the live KMA response at `var/verification/weather/jeju-live-data.json`, retaining only fields the parser uses. `cargo fmt`, `cargo clippy --all-targets -- -D warnings`, and `cargo test` passed (41 unit tests passed, four Redis-gated unit tests ignored, four integration tests passed). The six wind tests cover the 43-row fixture, item-time and calm behavior, root/row validation, missing and failed batch retention, and both routes sharing one source request.
