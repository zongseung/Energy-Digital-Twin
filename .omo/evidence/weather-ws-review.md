# Weather WebSocket transport review

**PASS (code and existing tests); no actionable transport defect found.**

- `Weather::run` is the single 60-second upstream poller. `poll` changes the RAM cache and signals one `tokio::watch` value after both successful and failed polls; socket subscribers read `stations_response` from that cache. Opening or reconnecting a socket does not fetch KMA data. The watch value is only a version signal, so slow subscribers receive the latest cache rather than queued history (`src/weather.rs:180-220`, `src/weather/stream.rs:49-81`).
- The WebSocket response uses the same `stations_response` as HTTP, including retained station rows and `source_fetch_failed` on source failure. The backend socket test confirms 43 initial rows, identical initial snapshots for two clients, a changed poll, stale rows after failure, latest state on reconnect, three upstream reads for three explicit polls, origin and capacity rejection, permit release, and shutdown close (`src/weather.rs:776-886`; `.omo/evidence/weather-ws-backend.md`).
- Upgrade checks the exact configured Origin allowlist when Origin is present, limits concurrent subscribers to 64, bounds inbound frames/messages to 16 KiB, times out writes after 5 seconds, sends 30-second pings, and drains subscribers within an 11-second deadline (`src/weather/stream.rs:15-93`, `src/weather.rs:162-177`, `src/main.rs:88-104`).
- Browser wind code has no HTTP wind poll. It keeps one connecting/open socket, closes on hidden tab, reconnects on visibility and close, rejects obsolete callbacks by socket identity, and uses 15-second first-frame and 90-second subsequent-frame deadlines. Its Node lifecycle check passed 20 hidden/reconnect cycles and malformed/silent-stream cases (`renderers/twin/app.js:269-313`, `var/verification/weather-ws/client-lifecycle.json`). Mock browser QA also passed automatic freshness expiry without fetching and socket-close behavior that retains the last reading while stopping direction following (`var/verification/weather-ws/mock-browser-qa.json`).

Live Chromium QA passed at 1280 px and 375 px: both pages rendered 43 rows and received a successful WebSocket handshake with a 43-row first frame; CDP captured zero wind HTTP GETs (`var/verification/weather-ws/live-browser-qa.json`). A separate 71-second single-page capture received three 43-row frames on one socket, with the latter two received 60 seconds apart, no wind HTTP GETs, and a fresh final browser state (`var/verification/weather-ws/live-long-qa.json`).

Limit: an immediate connection before the first upstream poll completes can receive an empty cache snapshot, followed by the first completed poll's station snapshot. The 43-row assertion applies once the collector has populated the cache.
