# 탐라 시설 3D

사용자가 2026-09-30 승인한 범위는 공개 제원·사진으로 추정한 시설 외형이다. 실제 공장의 사진/3D 대조 참조처럼 시설 자체의 부품과 입체 구조를 먼저 보여준다. 탐라 해상풍력 10기의 원천 좌표와 1m 단위를 유지한다. 사진 질감·실측 CAD·개별 운전 계측이 확보되었다고 표시하지 않는다.

기존 ../mock/DESIGN.md와 ../site/style.css의 중립 색상·글꼴·간격·44px 조작·focus 토큰을 재사용한다. 화면은 상단 제목, 가장 큰 3D 장면, 선택 시설 상세와 접을 수 있는 목록, 하단 실제 제주 집계다. 초기 시점은 터빈의 블레이드·나셀·타워·재킷을 식별할 수 있는 근접 사선 시점이며 단지 전체 보기로 실제 배열을 확인한다. 부품이 있는 GLB를 Three.js와 Omniverse에서 함께 사용한다.

모바일은 장면을 먼저 보이고 상세·목록·집계를 자연 흐름으로 배치한다. 별도 프레임워크·외부 폰트·자동 카메라 이동·합성 수급곡선은 없다. 시설 선택은 마우스 raycast와 동일 ID의 native button을 사용한다. 선택 및 카메라·회전·확대 버튼은 키보드로 접근한다. 회전자 애니메이션은 사용자가 켠 경우에만 시연하며 실측 RPM이 아님을 표시하고 숨겨진 탭에서는 중지한다.

확인된 단지 제원과 추정한 허브 높이·기초·방향은 상세에서 구분한다. 개별 실측 출력은 —이며 하단 API 값은 제주 집계라고 명시한다. 모델 로딩/실패, API 장애/지연, WebSocket 재연결 상태를 서로 분리한다. DOM은 textContent로 원천 문자열을 표시한다. manifest에 남긴 출처와 치수 가정은 검토 가능하게 제공한다.

375/768/1280px 실제 브라우저, 시설 선택, 카메라, 실제 API/장애 상태, GPU RTX 캡처를 검증한다. 확인 전 성능·전체 접근성 또는 실측 형상 일치를 완료로 주장하지 않는다.

## 송전망과 일부 지형 확장

2026-09-30 사용자 범위: 제주 송전선·HVDC 경로·변전소까지만, 지형은 일부만. 기존 외형/추정 승인과 기획서 §3·§14의 GIS 경로 표시를 적용한다. 배전 minor_line 5개는 이 장면에서 제외한다. 입력54개 중 같은 타입·전압·정방향/역방향 geometry가 완전히 같은 HVDC 중복3쌍은 원천 ID를 묶어 표시한다. 전기적 연결·흐름·부하율은 만들지 않는다.

상단 native button으로 탐라 풍력/제주 전력망을 전환한다. 전력망 전체는 원천 경로46개·변전소13개·해안선을 보여준다. 한림 지형 버튼은 서부 일부 DSM과 한림 선로 근접 시점으로 이동한다. 경로선은 화면 굵기의 GIS 표시이고 실제 전선 직경/매설 깊이가 아니다. 한림 대표 선로는 원천 수평 경로 위 추정 철탑·애자·처진 도체 메시를 가진다. 변전소는 원천 위치의 추정 설비 외형이다. 변전소 목록·선로 목록·상세·레이어 켜기/끄기는 기존 버튼/checkbox/dl을 재사용한다. 레이어 off는 목록에도 반영하며 가려진 선택을 지운다.

전력망 색 토큰: --transmission:#edc476 (송전 경로), --hvdc:#bb9def (HVDC), --cable:#83d5c1 (기타 케이블), --station:#efb0ac (변전소 원천 위치), --coast:#91afb0 (해안). 선택 색은 기존 --accent를 재사용하며 글자·선 굵기를 함께 바꾼다. 경로 색은 전압/부하 상태를 의미하지 않는다. 지형은 지형 고도와 원천 토지피복을 조합하되 자료가 없으면 단색 지형으로 명시한다. 전체 보기의 확대 표시선과 근접 물리 구조는 구분한다. 불필요한 자동 애니메이션은 없다.

검증은 경로 좌표·중복 보존·HVDC 제주 밖 끝점·동명 이종 전압 변전소 보존·배전 제외·실제 DSM 범위, GLB 부품과 유한 좌표, 브라우저 전환/선택/레이어/좁은 화면, 기존 풍력 복귀, 실제 RTX 근접 캡처를 확인한다. 미확인 물리 치수나 연결을 실측으로 표시하지 않는다.

사용자 후속 요청으로 PV 3개 등록 시설을 일부 추가한다. 서로 다른 등록 좌표를 선택하며 동일 좌표에 여러 허가 레코드가 있다는 한계를 기록한다. --pv:#9cbef5를 범례에 추가한다. 패널·프레임·지지대·인버터는 추정 모형, 등록 kW는 원천 용량이고 패널 수/실측 발전량으로 역산하지 않는다. PV 레이어·선택·근접 버튼은 기존 native 조작을 재사용한다.

## 현재 요구로 대체: 하나의 부분 장면

2026-09-30 후속 수정으로 풍력/전력망 모드 구분을 없앤다. 기존 탐라–한림 부분 DSM 위에 풍력10기·PV3곳·범위 내 변전소/송전선이 함께 존재한다. 시점 버튼은 같은 장면의 카메라만 변경한다. 범위 밖 해안·HVDC/시설은 제외하고 표시 선로를 경계에서 자른다. 원천 좌표는 재배치하지 않는다. 최초 시점은 풍력 배열과 육지를 함께 보며 구역 전체 버튼으로 부분 지형의 전체 범위를 확인한다. 별도 지도 탭 없이 모든 시설은 동일 목록/선택 상세를 공유한다. GPU 결과 링크는 통합 장면의 서버 RTX 캡처임을 표시한다. 이 문단이 위의 모드 전환 설계를 대체한다.

## 사진 기반 3D 자산의 지도 통합

사진을 TRELLIS.2로 변환한 GLB는 그 자체로 위치·미터 크기·시설 동일성을 알 수 없다. `var/rendering/photo-assets/manifest.json`에서 출처와 이용 조건, 원본·GLB hash, 시설 ID 대응 증거, 기준 길이와 방향의 근거, 모델 기준점·길이, 실제 기준 길이, Y-up을 확인한 정적 시설만 같은 `local/scene.glb`의 기존 시설 노드에 대체 배치한다. 입력이 없으면 장면은 기존 추정 메시 그대로다. 사진 기반 자산은 기준 길이만 검증된 추정 형상으로 표시한다. 풍력 회전자 pivot, 개별 터빈 동일성, 현장 도로·지물의 연속적인 다중시점 복원은 현재 자료로 확인되지 않아 이 경로에서 자동 채택하지 않는다. 별도 로드뷰 패널은 없다.

`facility_match_evidence`, `length_evidence`, `orientation_evidence`는 실제로 검토한 근거의 URL 또는 기록이다. 코드의 필수값 검사는 근거 내용의 진실성을 자동으로 판정하지 않는다. 기준점·길이 두 점은 생성 GLB의 장면 좌표이며 사진의 픽셀 좌표가 아니다. 원본 법선·재질·UV를 보존하고, 추론 단계의 `inference.run.check_glb`를 재사용해 외부 리소스가 없는 GLB만 허용한다.

```bash
uv run renderers/twin/test_photo_assets.py
uv run renderers/twin/build_local.py --self-test --output var/rendering/local-candidate
```

CLI는 임시 출력의 검증을 통과한 파일만 지정한 출력 디렉터리에 교체한다. 운영 데이터가 준비된 GPU 작업 공간에서 실행한다. 네이티브 엔진 검증용 합성 장면이 필요하면 테스트에 `--keep-scene /tmp/photo-placement-fixture`를 지정한다. 이 합성 장면을 운영 데이터로 배포하지 않는다. 실제 사진 후보와 남은 입력은 [채택 판정 문서](../../docs/photo-asset-adoption.md)에 기록했다.

## 신창 절차적 건물과 z19 지붕 영상 (2026-09-30)

사용자는 높이 상자를 거부했다. `var/rendering/site/scene.json`의 윤곽 2,661동을 모두 원천 위치·윤곽 그대로 세우고 기본 표시한다. 벽 높이는 원천 양수 높이(`provider` 623동) → 층수×3.0 m(`floors_estimated` 887동) → 1층 3.5 m(`default_estimated` 1,151동) 순서다. 0·NaN·무한 높이는 원천 높이로 쓰지 않는다. 원천 높이가 처마 높이인지 정의가 없어 벽(처마선) 높이로 쓴다.

지붕: 단일 링이고 최소 회전 사각형의 85% 이상을 채우며 조적·블록·석조·경량철골·강파이프이거나 속성 없는 1층이면 박공이다. 주택·무속성은 20°(`gable_house` 1,672동), 창고·동식물은 10°(`gable_shed` 113동)이며 긴 변이 용마루, 처마 0.4 m, 박공 끝벽을 닫는다. 나머지(ㄱ자·중정·철근콘크리트 등)는 평지붕과 0.2×0.6 m 난간(`flat_parapet` 876동)이다. 박공면과 난간은 `building_<id>_roof`, 벽·박공 끝벽은 `_walls`다.

지붕 색은 `prepare_imagery.py --roofs`가 윤곽 bbox+1 m와 겹치는 VWorld Satellite z19 타일 747장만 받아 건물별로 잘라 붙인 4096×2679 atlas 한 장이다. 지붕 정점은 EPSG:3857로 투영해 자기 칸 안의 UV를 가진다. 칸 밖 처마 모서리는 칸 가장자리로 고정한다. 타일 실패·빈 타일이 있으면 그 건물은 회색 지붕과 `roof_texture: unavailable`로 둔다. 첫 수집에서 시간 초과 2장으로 6동이 이 경로를 탔고, 재시도 뒤에는 2,661동 모두 영상이 있다. 외벽은 빌드 시 PIL로 만든 512² 절차적 텍스처다(미장+창·1층 문 2,422동, 금속 골판 197동, 현무암 42동). UV는 미터 단위이며 u=길이/4 m, v=높이/(4×층고)라서 층마다 창 한 줄이 생긴다.

화면: 레이어 라벨은 `건물 · 위치·윤곽·지붕영상 실제 / 형태·외벽·일부 높이 추정`이다. 건물을 누르면 기존 상세 목록에 원천 ID, 벽 높이 근거, 지붕 규칙, 영상 유무가 보인다. 시설 목록 21개는 그대로다. 한계: 지붕 형태·외벽 색·창 배치·추정 높이는 실측이 아니다. 우진각 지붕 영상이 박공면에 투영될 수 있고, 처마 가장자리에 주변 지면이 비칠 수 있다. 지반은 DSM 근사다. `app.js`는 아직 숨긴 `#buildings-count`에 예전 문구를 쓰고, 마을 시점 제목도 예전 문구다. 둘 다 통합 단계에서 고친다.
